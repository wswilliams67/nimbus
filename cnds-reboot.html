    v1 Reboot
    This application is not optimized for small screens. Please use a large tablet, laptop, or desktop computer to continue.

    Reboot is Nimbus CNDS's foundational CSS normalization layer — a carefully scoped collection of element-specific style declarations that ships in css/core/reset.css. It builds on top of the browser's own stylesheet to eliminate cross-browser inconsistencies and establish a clean, predictable baseline before any component or utility class is applied. Unlike a full CSS reset (which strips all browser defaults), Reboot takes an opinionated approach: it preserves sensible defaults, corrects known quirks, and applies a small set of global conventions — all using element selectors and CSS custom properties from css/core/variables.css so every value remains themeable and overridable without touching the source.

    In practical terms, Reboot normalizes box-sizing to border-box across every element, sets a consistent font-family, font-size, line-height, and color on <body>, resets margin-top on headings and paragraphs (preventing collapsing margin surprises), normalizes list padding-left on <ul> and <ol> elements, and brings form elements — <input>, <select>, <textarea>, and <button> — into typographic alignment with the rest of the page by setting line-height: inherit and removing browser-injected margins. Focus indicators are explicitly preserved on interactive elements to satisfy WCAG 2.1 SC 2.4.7 and Section 508 requirements; Reboot never removes :focus outlines without providing a visible alternative.

    Approach

    Reboot provides many HTML elements with opinionated styles using only element selectors. Additional styling is done only with classes. For example, we reboot some <table> styles for a simpler baseline and later provide .table, .table-bordered, and more.

    Here are our guidelines and reasons for choosing what to override in Reboot:

    • Update some browser default values to use rems instead of ems for scalable component spacing.
    • Avoid margin-top. Vertical margins can collapse, yielding unexpected results. More importantly though, a single direction of margin is a simpler mental model.
    • For easier scaling across device sizes, block elements should use rems for margins.
    • Keep declarations of font-related properties to a minimum, using inherit whenever possible.

    Page defaults

    The <html> and <body> elements are updated to provide better page-wide defaults. More specifically:

    • The box-sizing is globally set on every element—including *::before and *::after, to border-box. This ensures that the declared width of element is never exceeded due to padding or border.
      • No base font-size is declared on the <html>, but 16px is assumed (the browser default). font-size: 1rem is applied on the <body> for easy responsive type-scaling via media queries while respecting user preferences and ensuring a more accessible approach. This browser default can be overridden by setting --cnds-font-size-base in your theme overrides.
    • The <body> also sets a global font-family, font-weight, line-height, and color. This is inherited later by some form elements to prevent font inconsistencies.
    • For safety, the <body> has a declared background-color, defaulting to var(--cnds-body-bg).

    Native font stack

    Nimbus CNDS uses a "native font stack" or "system font stack" for optimum text rendering on every device and OS. These system fonts have been designed specifically with today's devices in mind, with improved rendering on screens, variable font support, and more. Read more about native font stacks in this Smashing Magazine article.

    CSS

    :root {
  --cnds-font-family-base:
    /* Cross-platform generic font family (default user interface font) */
    system-ui,
    /* Safari for macOS and iOS (San Francisco) */
    -apple-system,
    /* Chrome < 56 for macOS (San Francisco) */
    BlinkMacSystemFont,
    /* Windows */
    "Segoe UI",
    /* Android */
    Roboto,
    /* Basic web fallback */
    "Helvetica Neue", Arial,
    /* Linux */
    "Noto Sans",
    "Liberation Sans",
    /* Sans serif fallback */
    sans-serif,
    /* Emoji fonts */
    "Apple Color Emoji", "Segoe UI Emoji", "Segoe UI Symbol", "Noto Color Emoji";
}

    Note that because the font stack includes emoji fonts, many common symbol/dingbat unicode characters will be rendered as multi-colored pictographs. Their appearance will vary, depending on the style used in the browser/platform's native emoji font, and they won't be affected by any CSS color styles.

    This font-family is applied to the <body> and automatically inherited globally throughout Nimbus CNDS. To switch the global font-family, update the --cnds-font-family-base CSS variable in your theme overrides.

    Forms

    Various form elements have been rebooted for simpler base styles. Here are some of the most notable changes:

    • <fieldset>s have no borders, padding, or margin so they can be easily used as wrappers for individual inputs or groups of inputs.
    • <legend>s, like fieldsets, have also been restyled to be displayed as a heading of sorts.
    • <label>s are set to display: inline-block to allow margin to be applied.
    • <input>s, <select>s, <textarea>s, and <button>s are partially addressed by the browser stylesheet, but Reboot removes their margin and sets line-height: inherit, too.
    • <textarea>s are modified to only be resizable vertically as horizontal resizing often "breaks" page layout.
    • <button>s and <input> button elements have cursor: pointer when :not(:disabled).

    HTML5 [hidden] attribute

    HTML5 adds a new global attribute named [hidden], which is styled as display: none by default. Nimbus CNDS reinforces this default by declaring [hidden] { display: none !important; } to help prevent its display from getting accidentally overridden by other styles.

    HTML

    <input type="text" hidden>

    To merely toggle the visibility of an element, meaning its display is not modified and the element can still affect the flow of the document, use the .invisible class instead.

    API Documentation

    Introduction

    Reboot is CSS-only and requires no JavaScript initialization. It applies element-level baseline styles globally via css/core/reset.css using element selectors and CSS custom properties defined in css/core/variables.css. Theme-specific values (light/dark colors) are set in css/themes/light.css and css/themes/dark.css and override the base defaults automatically when a theme is active.

    Usage

    Override any CSS custom property in your application's stylesheet after the Nimbus CSS imports. Scoping overrides to :root applies them globally; scoping to a selector restricts them to that element and its descendants.

    CSS
    /* Global override in app.css */
:root {
  --cnds-font-family-base: "Inter", sans-serif;
  --cnds-font-size-base: 0.9375rem;
  --cnds-line-height-base: 1.6;
  --cnds-body-color: var(--cnds-primary-gray-700);
  --cnds-body-bg: var(--cnds-surface-light-100);
}

/* Scoped override */
.my-section {
  --cnds-link-color: var(--cnds-product-casefusion-green-500);
  --cnds-link-hover-decoration: underline;
}

    Accessibility

    Reboot is designed to preserve and enhance browser accessibility defaults rather than strip them. The following notes document key accessibility behaviors and requirements when working with Reboot styles.

    Focus indicators

    Reboot never removes :focus outlines without providing a visible alternative. Interactive elements — links, buttons, inputs, selects, and textareas — retain browser-default focus rings unless explicitly overridden by nimbus.css component styles that provide equivalent or superior visibility. If your application overrides focus styles (e.g., outline: none), you must replace them with a WCAG 2.1 SC 2.4.7 compliant visible indicator such as a box-shadow focus ring using var(--cnds-focus-ring-color).

    Variable Description
    --cnds-focus-ring-color Theme-defined focus ring color used by Nimbus component focus styles. Override in app.css to apply globally.
    --cnds-focus-ring-width Width of the focus ring box-shadow offset. Default: 3px.
    List semantics with list-style: none

    Some browsers (notably Safari with VoiceOver) strip list semantics when list-style: none is applied via CSS. If your application or a Nimbus utility class removes list markers for visual reasons, add role="list" to the <ul> or <ol> element to preserve the semantic announcement to screen readers. This is required for WCAG SC 1.3.1 Info and Relationships and Section 508 §1194.22. 

    <!-- Preserve list semantics when list-style: none is applied -->
<ul class="list-unstyled" role="list">
  <li>Item one</li>
  <li>Item two</li>
</ul>
    Form element accessible defaults

    Reboot normalizes form elements without removing their accessible defaults. The following behaviors are intentionally preserved:

    • Label association: <label for="id"> associations are unaffected by Reboot. Always pair every visible label with its input via for/id or wrapping.
    • Fieldset/legend: While Reboot removes the default border and padding from <fieldset>, the element retains its ARIA grouping role. <legend> continues to provide the accessible name for the group.
    • Disabled state: Disabled form elements (via the disabled attribute) suppress the cursor: pointer rule applied by Reboot, maintaining the expected not-allowed cursor behavior.
    • Resize behavior: Reboot restricts <textarea> resize to vertical only. This prevents layout disruption that could obscure adjacent interactive elements and indirectly affect keyboard navigation.
